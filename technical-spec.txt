Technical Spec — Toyota Parts Admin Panel
1. Project Overview

An internal admin dashboard for a small business owner selling Toyota Land Cruiser/Hilux parts (new, used, and strip-for-spare vehicles). The panel manages the public-facing site's content (pages, blog, templates), commerce (products), audience (users, mailing list), and oversight (analytics, updates) — all through a low-friction, accessibility-first UI.

Design constraint that shapes everything: the primary user is not technical and has visual reading strain. Every screen should favor plain language, generous spacing/contrast, and forgiving interactions (confirmations before destructive actions, autosave, undo) over density or cleverness.

3. Accessibility Baseline (applies to every module below)

Given the target user explicitly needs visual/reading accommodation:

	* WCAG 2.1 AA minimum as the floor, not the ceiling
	* Base font-size ≥ 18px, with a user-toggleable "larger text" mode (persisted per admin user)
	* High-contrast color palette by default; avoid relying on color alone for status (use icon + text, e.g. "✓ Published" not just a green dot)
	* Icon-only buttons are disallowed — every action button gets a visible text label
	* Forms: one clear task per screen where possible, large touch targets, inline validation with plain-language errors ("This field can't be empty" not 
	  "Validation failed: 422")
	* Destructive actions (delete product, remove user, unpublish page) always require a confirmation modal that names what will be affected
	* Autosave drafts for long content (blog posts, pages) so nothing is lost
	* Image uploads require alt-text input — make it required, not optional, since the user manages product photography and alt text helps her own site's 	
	  accessibility too
	* Keyboard navigability and semantic HTML (<nav>, <main>, <button> not <div onclick>) throughout

6. Roles & Permissions

+-----------------------+---------------------------------------------------------------------------------------+
| ROLE                  | CAN DO / PERMISSIONS                                                                 |
+-----------------------+---------------------------------------------------------------------------------------+
| Owner/Admin           | Everything, including managing other users' roles.                                     |
| Editor                | Pages, blog, products, media — cannot access users or settings.                       |
| (Front-end) Subscriber| Not a panel role at all — just a mailing-list/customer record with no admin access.   |
+-----------------------+---------------------------------------------------------------------------------------+

Store permissions as a jsonb column on roles so you can adjust without schema migrations later.

7. Non-Functional Requirements

Security: Hashed passwords (bcrypt), CSRF tokens on all forms, rate-limited login, parameterized queries throughout (handled by Knex), and file-upload type/size validation.

Performance: Fast server-rendered pages by default with this stack; media served via CDN or optimized static hosting as volume grows.

Backups: Scheduled PostgreSQL backups (a daily pg_dump cron job is sufficient at this scale).

Audit Trail: Log of changes made to products, pages, and users -- useful for a non-technical owner to track "what changed."
